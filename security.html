Security

Protect the data. Protect the decision.

TruWorth is designed to minimise unnecessary exposure of user data and keep protected decision logic away from the public browser where practical.

Last updated 15 October 2026

1. Security principles

Least data necessaryWe aim to collect only data needed to provide assessments, profiles, subscriptions and requested features.
Authenticated accessSigned-in data is accessed through authenticated application flows and user-scoped backend controls.
Server-side protected logicProprietary recommendation coefficients and protected calculations are kept behind authenticated server functions rather than published in browser code.
Secure transportProduction access is provided over HTTPS through managed hosting and backend providers.

2. Account security

Use a unique password and protect access to the email account associated with TruWorth. Do not share authentication links or credentials. If you believe your account has been compromised, change your password and contact us promptly.

3. Infrastructure and providers

TruWorth uses specialist infrastructure providers for hosting, authentication/database services, payments and transactional communications. Security responsibilities are shared: providers secure their platforms, while TruWorth is responsible for its configuration, application logic, access controls and data handling.

4. Application protections

Current controls include authenticated server functions for protected operations, user-scoped database access controls, restrictions on unsafe product-import destinations, input validation, server-side subscription and recommendation checks, and separation between partner monetisation and recommendation scoring. Hosting and browser-security configuration is reviewed as the production environment changes.

5. No system is unhackable

No internet service can honestly guarantee absolute security. TruWorth therefore uses layered controls, limits unnecessary exposure, keeps sensitive decision coefficients server-side and aims to respond quickly to credible issues.

6. Prohibited security activity

Without prior written authorisation, you must not attempt credential attacks, exploit vulnerabilities, access another user's data, bypass authentication or subscription controls, interfere with availability, deploy malware, perform destructive testing, exfiltrate data, or run high-volume automated scanning against TruWorth.

7. Responsible disclosure

If you believe you have found a security vulnerability, report it privately to partnerships@ramellacorporateconsulting.com. Include the affected URL or feature, a clear description, reproduction steps and the potential impact. Do not include unnecessary personal data or publicly disclose an unresolved issue before we have had a reasonable opportunity to investigate.

8. Security incidents

Where a security incident affects personal data, we will assess the incident and take steps required by applicable data-protection law, including regulator or individual notification where the legal threshold is met.

9. User responsibility

You remain responsible for the security of your own device, browser, email account and credentials. Third-party retailer links, payment pages and other external services operate under their own security arrangements.
